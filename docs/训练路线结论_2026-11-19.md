## 2. 路线结论

### 2.1 保底主力（不动）：9d6e 家族 + 端口权重

- 唯一被 LB 反复验证到 **964–1011** 的臂；不需要额外训练；
- 代表 = `p9d6e`（`build/agents/p9d6e`，权重 `build/port_plain/model.pt`，卡组 `dunsparce_abra__9d6e`）；
- 变体 `db04`（差 2 张）与 `0bf5`（差 4 张）已合并进 9d6e（`decks/deck_merge.txt`），不再各自养驾驶员。

### 2.2 唯一值得继续训的进攻线：e1d7

| 理由 | 数据 |
|---|---|
| 天花板最高 | 外部 1600.4（榜一 knshnb，144 局 66.0%，同卡组哈希 `e1d754a7`） |
| 我们已经能打上去 | `candE1D7T` 峰值 **992.1**，与 9d6e 同档 |
| 面板低估它 | 面板 41.6%，但面板对手是端口驾驶员，与真实场分布不符（§8） |
| 训练目标明确 | 下一轮 `e1d7_r2`：bank 换成 **3eaa×2 / 0904 / 8fe3 / beldum／镜像 / 守格**，**去掉 dunsparce 系**（榜前 20 队里 dunsparce 只占 0bf5 14 局 28.6%，根本不在主流） |

判据（预注册）：`e1d7_r2` 与 `candE1D7T` **同快照** LB 对比，**Δ ≥ +30 分**才算赢；
否则 e1d7 线也只用来守，不再加投。

### 2.3 降级/放弃：beldum 系、dreepy 3eaa

| 牌 | 证据 | 处置 |
|---|---|---|
| `a47a` beldum | LB **259.3**（端口驾驶员完全不会打）；榜前队用它 105 局只有 **37.1%** 胜率 | 不投训练；只作为"对手牌"补种子 |
| `3eaa` dreepy | BC 驾驶员 LB 855.6（比 9d6e 低 100+）；榜前队 177 局 52.5% | 只作对手牌；若将来要打，需专门训练且先证明微调有增益（目前证据是不行） |
| `0904` / `8fe3` / `0b34` / `cb25` / `5b8f` | 只有覆盖率与天花板，本地无驾驶员、无对位数据 | 先补种子（本轮正在跑），按投资分排队，暂不投训练 |

### 2.4 一个必须修的东西：我们自己的镜像格是 0%

回放里面对 dunsparce 系对手 **4 局全输**。这是因为我们的主牌就是 dunsparce 系，
对手用同系时我们的驾驶员没有针对性（面板里镜像格 49–53%，纯噪声）。
⇒ 下一步如果继续用 9d6e 家族，**镜像格是唯一真有提升空间的地方**（可以做"同系对抗"专项 bank）。

## 3. 每轮的固定动作（写死）

1. **提交（2026-11-19 用户改规矩）**：**不再留"守分锚"**——"一开始分数高没什么用，
   怎么能方便训练就怎么提交"。所以每天 2 个计分位**全部用来探针**，挑对本轮训练最有信息量的两支：
     · 优先：**验证训练改动**（例如 `candE1D7R2` vs `candE1D7T` 同快照对比）；
     · 其次：**测新牌区间**（本地没有驾驶员的牌，用端口/BC 权重先量出它在真实场的量级）。
   读数要**同一快照读多次**（间隔 ≥30 分钟），记中位数与极差；单次数字不进结论。
2. **判强度**：LB（同快照）> 回放胜率 > 自家面板（面板只用来发现"结构性短板"，不用来排序）。
3. **训练**：GPU 只投 e1d7_r2；跑完立刻 `finish_run_generic.sh`（md5 → 转 pt → 关 GPU → 推评估机 → 面板 → 关机）。
4. **表维护**：`bash tools/refresh_tables.sh`（含必须卡组覆盖闸门、淘汰闸门、同构卡组合并）。
