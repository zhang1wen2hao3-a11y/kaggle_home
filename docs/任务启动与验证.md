# 任务启动与验证纪律（写死，2026-11-17 用户要求）

> 一句话：**起任务之后 10~20 秒内必须确认"远端真在跑、产物真在长、日志没有致命错误"，
> 不许用长 sleep 等结果。** 起来就等着报数；没起来就立刻修。

## 1. 固定的三步验证

```bash
# ① 起任务（后台话，别阻塞）
./tools/py tools/dispatch_panel.py --cands X --cells ... > logs/dispatch_X.log 2>&1 &
# ② 立刻验证（10~20 秒一轮，最多 6 轮 ≈ 72 秒）
bash tools/verify_launch.sh root@HOST 'pgrep -fc "ptcg_league/[e]val_pair" || true' '/root/dispatch_*.log'
# ③ 通过后才是"等它跑完"：由调度器自己打进度，不再人工 sleep 轮询
```

`tools/verify_launch.sh` 检查三件事：
1. 探针输出**数字 > 0**（真有进程）；
2. 关键日志 glob 里没有 `Traceback / AssertionError / MISSING_AGENT / 不存在`（有就直接失败并打印尾部）；
3. 连续 6 轮（每 12 秒）都是 0 ⇒ 判定"没起来"，打印远端日志尾部并非零退出。

`tools/eval_candidate_realpanel.sh` 已内置这一步：派活后对每台机器跑一次验证，任一失败立即中止。

## 2. 为什么定这条规矩：两次白等

| 事故 | 表象 | 真实原因 | 现在怎么挡 |
|---|---|---|---|
| **2026-11-16 23:03 → 03:27（4 小时 GPU 空转）** | 收尾脚本"等 final.bin"一直不退出 | ①`ssh` 端口写成大写 `-P`（新版 OpenSSH 里 `-P tag` 是"给连接输出打标签"，端口参数被吃掉、主机解析成垃圾地址）② `pgrep -c ... \|\| echo 0` 无匹配时输出 `"0\n0"`，与 `"0"` 比较永远不等 | 端口统一小写 `-p`；命令替换加 `head -1`；等模型一律用"文件大小 + 进程数"双条件，且**先手动探一次**再进循环 |
| **2026-11-17 04:0x（评测两轮没派出去）** | 调度器显示 17 个任务全 `pending`，机器闲着 | `decks/testset_meta_real.tsv` 里老 12 格的 `agent_dir` 写成了裸名（`port_7e39`），远端 `[ -d port_7e39 ]` 不成立 ⇒ 每个任务都在远端被静默跳过 | ①生成器统一写 `build/agents/...`；②起任务后必须跑 `verify_launch.sh`，探针为 0 立刻暴露 |

## 3. 配套的"探针"写法（踩过的坑）

- **`pgrep` 必须用拆写模式**：`ptcg_league/[e]val_pair`。写成 `ptcg_league/eval_pair` 会匹配到
  **自己这条 ssh 命令行**，于是每台机器永远"忙"，调度器一个活都不派（11-16 卡了半小时）。
- **数字归一化**：`case "$out" in ''|*[!0-9]*) out=0;; esac`，别让空串/多行把比较搞坏。
- 远端日志路径要传到 `verify_launch.sh`，失败时它会自动 `tail -12`，一眼看到 assert/真因。

## 4. 与调度器分工

- **调度器**（`tools/dispatch_panel.py`）负责"持续排满机器 + 自愈重排"，不负责人工判断；
- **启动验证**（`tools/verify_launch.sh`）负责"这一炮到底有没有发出去"；
- **结果聚合**（`tools/real_panel_agg.py` 等）负责"跑完之后的数"。
三者分开，任何一步坏了都只影响自己那一环，不会静默污染结论。
