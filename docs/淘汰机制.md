# 卡组淘汰机制（与新增建议）

用户 2026-11-19 定的规则（原话）：
> 如果卡组强度全面低于其他卡组，除了冠军卡组，或者部分格子可以给我们的卡组部分压力，
> 后续我们应该有个淘汰机制，如果卡组强度不行，且没有给我们表格里的卡组部分格子压力，
> 在环境中也没有覆盖率，那么就应该被淘汰。

## 1. 判定式（`tools/prune_decks.py`）

**淘汰 = 三个条件同时成立**（缺一不可，避免误杀"弱但很毒"的牌）：

| 条件 | 阈值 | 口径 |
|---|---|---|
| ① 强度全场最低 | `S_best == min(S_best)` | `S_best` = `docs/the-pockmon-battle-choices-win-rate.csv` 里该牌**行均值**（各牌用它最强驾驶员实战）；另附 `S_init`（`in-table` 里 init-vs-init 行均值，只比牌不比驾驶员）作参照 |
| ② 没有格压力 | `P < 55%` | `P(d)` = d 用**自己最好的驾驶员**当对手时，对表内各卡组的最高胜率（数据来自 `the-pockmon-battle-choice-in-table.csv`） |
| ③ 环境无覆盖率 | `C < 2%` | `docs/必须卡组清单.csv` 的 `对手覆盖率`（我方对局 + 榜前队回放，合计 1167 次出场） |

**保护条款**（"除了冠军卡组"）：
- 强度冠军（`S_init` 最高）与投资分冠军一律保留；
- **外部天花板 ≥ 1500 的牌一律保护** —— 有顶级玩家靠它上分（如 `26c6`：ミワハルキ 1594、1000 局 56.7%），
  我们的端口驾驶员打不好不代表牌不行，这种牌不能按"我们测出来弱"就淘汰。

两个必须注意的测量坑（都已在代码里处理）：
1. `0d86`（shuppet）用 **init 驱动只有 5.5%**（端口根本不会打这副牌），
   于是 12 副牌"打 0d86"都在 97–100% —— 这是"端口不会打"，不是牌强弱。
   ⇒ 算格压力时，若 d 有专属驾驶员就**只看 d 用专属驾驶员的单元**；
   挑战方明明有专属驾驶员却拿 init 上场的单元也丢掉。
2. `the-pockmon-battle-choice.csv` 的驾驶员矩阵里，强驾驶员会把自己的分记到牌上（0d86 挂 g8_bc_parent）。
   所以强度用 `S_best` 排序、但淘汰还要 `S_init` 不至于全场最高，避免"一个强驾驶员掩盖牌本身很弱"。

## 2. 当前结论（2026-11-19 首跑）

`docs/卡组淘汰与新增建议.csv`：维护表 12 副，**淘汰 0 副**，建议新增 16 副。

**没有一副满足淘汰三条件**。最接近的是 `26c6`（强度全场最低 33.7%、格压力 26%、覆盖率 0.2%），
但它被"冠军级保护"挡住（外部天花板 1594 ≥ 1500）。

**值得盯的"靠格压力活着"的牌**（覆盖率 ≈0，一旦格压力掉到 55% 以下就会被淘汰）：

| 卡组 | 覆盖率 | 格压力 | 说明 |
|---|---|---|---|
| `db04` | 0.0% | 85%（打 e1d7） | 强度冠军（65.4%），但真实场里几乎没人用 |
| `9d6e` | 0.3% | 95%（打 e1d7） | 同上 |
| `f5f8` | 0.3% | 70%（打 26c6） | 同上 |
| `e8ee` | 0.9% | 95%（打 26c6） | 只靠一个格子活着 |
| `0d86` | 0.1% | 63%（打 26c6） | 强度靠 g8_bc_parent，覆盖率极低 |

## 3. 建议新增（不进表 = 盲区）

按投资分排序，前几副（覆盖率 ≥2.5%）：

| 卡组 | 覆盖率 | 投资分 | 远端天花板（玩家） |
|---|---|---|---|
| `a47a` beldum_metang | **10.8%** | 73.7 | 1278（SeaGoat） |
| `8fe3` dreepy-drakloak | 4.1% | 54.4 | 1318（tyr1218） |
| `9180` unseen | 2.8% | 47.1 | 1284（Swag Collectors） |
| `0b34` tealmaskogerponex-forestofvitality | 2.7% | 47.7 | 1334 |
| `5b8f` dreepy-drakloak | 2.7% | 47.2 | 1311 |
| `cb25` beldum-metang | 2.6% | 46.0 | 1285 |
| `049c` dreepy-drakloak | 2.5% | 45.5 | 1291 |

**建议**：先加 `a47a`（beldum，榜前 20 队打了 124 局、覆盖率 10.8%）—— 这是目前维护表里**完全没有**的
一个原型，且远端有 SeaGoat 1278 的天花板；`8fe3/049c/5b8f` 是 dreepy 变体，可与既有 3eaa 归为一族。

增量顺序建议：`a47a` → `8fe3` → `0b34` → `9180`；其余等覆盖率高过 2% 再说（否则又是"低覆盖陷阱"）。

## 4. 闸门

`tools/refresh_tables.sh` 第 ⑨ 步是 `prune_decks.py --check`：**只要有卡组同时满足淘汰三条件却仍在维护表里，
整条刷新非零退出**（退出码 4），并打印该牌的三项证据。淘汰是结构性改动（要动
`the-pockmon-battle-choice*.csv` 三张表 + 母表数据源），所以做成"拦下来人工处理"，不自动删行。
