## 2. 踩过的坑（都修在脚本里了，手搓命令时注意）

| 坑 | 现象 | 处理 |
|---|---|---|
| 榜单是 zip | 文件名 `the-pokemon-...-playground.zip`，**不含 "leaderboard" 字样** | 按 mtime 找最新的 `*.zip`，别再按关键字找 |
| CSV 带 BOM | 第一列变成 `﻿Rank` | 用 `encoding="utf-8-sig"` |
| TeamId vs 队名 | `team-submissions` 只吃数字 TeamId | 先从榜单 CSV 取 `TeamId` |
| VALIDATION 局 | 混在 episodes 列表里，不是真实对局 | 过滤 `EpisodeType.VALIDATION` |
| 回放落在 cwd | CLI 把 json 丢在当前目录，不在 `--out` 目录 | 下载后 `os.replace` 搬进目标目录 |
| 频率限制 | 太快会 429，且**静默少抓** | `--sleep 1.2`（默认），大批量用 1.5–2 |
| 旧提交是旧模型 | 一个队有 20+ 个 submission，卡组/权重都在变 | 只取**最近 2 个** submission 的对局 |
| 文件已存在 | 重复抓浪费 10 MB×N | 脚本按 `episode-<id>-replay.json` 存在即跳过 |

## 3. 抓回来怎么用（这步才是重点，别只抓不看）

回放 json 的关键字段：`steps`（每步的双方状态+动作，给 `framework.replay.decks_of()` 抽出双方 60 张卡组）、
`rewards`（终局奖励；两方相等或 `None` ⇒ 平/无效，丢弃）、`info.Agents[].Name`（队/玩家名）。

```python
import sys, hashlib; sys.path.insert(0, '.')
from framework.replay import decks_of
dk = decks_of(ep['steps'])                       # {0: [60 个卡号], 1: [...]}
h8 = hashlib.sha256(','.join(map(str, sorted(dk[i]))).encode()).hexdigest()[:8]
```

**卡组身份 = `sha256(','.join(sorted(card_ids)))[:8]`**，池子文件名是 `<archetype>__<8hex>`（部分旧文件只有 4 hex 前缀）。
先按 8-hex 精确匹配，匹配不到再退回 4-hex，仍不到就是 `未入库:<4hex>`。

四件必做的分析（都有现成脚本）：

| 要回答的问题 | 做法 |
|---|---|
| 榜前 N 队**用什么牌、赢多少** | 遍历回放 → 每方卡组哈希 → 局数/胜率聚合（2026-11-18 实跑：434 局里 `e1d7` 144 局 **66.0%**、`3eaa` 177 局 52.5%、`0bf5` 仅 14 局 28.6%） |
| 高手用的牌**和我们池子是不是同一副** | 8-hex 与 `decks/pool_field/*.csv` 比对（e1d7 的 5 个玩家全是 `e1d754a7`，和我们那副完全一致 ⇒ 差距在驾驶员不在卡组） |
| 高手**打谁赢/打谁输** | 按对手卡组拆胜负（`docs/高分玩家对位表.csv`，`tools/highrank_matchups.py`） |
| 我覆盖了哪些、漏了哪些 | `tools/top_team_decks.py`（每队每牌的局数/胜率 + 覆盖标记 17格/母表/池） |

## 5. 一句话总结（背下来）

> **榜单 CSV（zip 里）取 TeamId → `team-submissions` 取最近 2 个 ref → `episodes` 去 VALIDATION →

```text
$ kaggle competitions team-submissions 17153775          # 17153775 = knshnb
      id  dateSubmitted               publicScore
--------  --------------------------  -----------
58506973  2026-11-18 11:15:35.070000  1600.4          ← 这个 id 就是后面的 subRef
58427756  2026-11-16 11:01:23.620000  1508.2

       id  createTime      endTime      state                   type
126381493  2026-11-09 …      2026-11-09 …  EpisodeState.COMPLETED  EpisodeType.EPISODE_TYPE_VALIDATION
```
- 类型串是 `EpisodeType.EPISODE_TYPE_VALIDATION`（带前缀），真实对局是 `EPISODE_TYPE_*` 其它值 ⇒ 判据写"**包含 VALIDATION 就跳过**"。
- `episodes` 末尾会提示还有一条命令：`kaggle competitions logs <episode_id> <agent_index>`
  —— 想逐动作复盘某方的日志时用它（回放 json 里也能看，但 logs 更细）。
- `replay` 落盘名固定为 `episode-<episode_id>-replay.json`（约 10 MB）。
