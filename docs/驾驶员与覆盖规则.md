# 驾驶员表 · 覆盖规则与固定评测流程（我的记忆文档）

> 这份文件是**规则本身**，不是结论。任何一次"该格用哪个驾驶员 / 该驾驶员的胜率是多少"的
> 更新，都必须走这里的流程；违反流程得到的数字，不许写进交付表。
> 交付表 = `docs/the-pockmon-battle-choice.csv`（逐格：该格派谁）
> + `docs/the-pockmon-battle-choices-win-rate.csv`（该驾驶员的胜率）
> + `docs/the-pockmon-battle-choice-self.csv`（每副牌的最佳驾驶员）
> 母表 = `docs/the-pockmon-battle-choice-in-table.csv`（唯一证据源，其余全部由它重算）

## 0. 这张表是干什么用的（别再搞错）

**它是训练时的"最强驾驶员名单"**：`tools/choice_to_banks.py --strong` 读它决定
每个对手卡组派谁驾驶 → 生成 `BANKS/BANKDECKS` → 冻结 league 对手。
`tools/make_testset_A.py` 也读它（`-self` 那版）决定评估测试集里每个对手派谁。

⇒ 表里出现的**任何**名字，都必须能被 `tools/driver_registry.py` 解析成
「agent 目录 / 本地权重 / GPU 机上的 .bin」。解析不了 = 训练实际上在打弱端口，而记录写成强驾驶员。

## 1. 覆盖（替换）规则 —— 写死在代码里，不许手改表

实现：`tools/build_from_master.py`（`THRESH_CELL=5.0`、`THRESH_ROW=1.0`、`VERIFIED_N=400`）

### 1.1 格级（`-choice.csv`）

| 条件 | 规则 |
|---|---|
| 替换 init | 候选驾驶员必须 **胜率 − init ≥ 5.0pp**，**且** 该格池化样本 **n ≥ 400** |
| 多个候选都过线 | 取 `(胜率, n)` 最大的那个 |
| 对角镜像格（我方=对手） | 写**当前内战最强的驾驶员**（该格胜率最高且 n≥400）；矩阵胜率一律记 **0.5**（镜像期望值） |
| 没有任何候选过线 | 填 init（不是"没数据"，是"没有已验证的更强驾驶员"） |

### 1.2 行级（`-self.csv` / `-win-rate-pilot.csv`）

| 条件 | 规则 |
|---|---|
| 换行级驾驶员 | 该驾驶员在整行上的**场权重加权**得分比 init 高 **≥ 1.0pp** |
| 权重口径 | 两套并存，**禁止混用**：`decks/weights_field_b05.txt`（我们 12 格实测占比，默认）、`decks/weights_top.txt`（LB≥1350 的天梯高分段份额） |
| 输出 | 默认口径 → `-choice*.csv / -win-rate*.csv`；顶分段口径 → 加 `--weights decks/weights_top.txt --suffix _top` |

### 1.3 母表去重（最容易"互相覆盖"的地方）

同一条记录键 = **(我方卡组, 对手卡组, 我方驾驶员, 对手驾驶员)**，只保留
`(来源优先级, n)` 最大的那条。**来源优先级：`meta:` 3 > `panel7:` 2 > `matrix:` 1`、`vsopp:` 1**。

⇒ 同一个驾驶员在"7 格历史面板（n≈180）"和"12 格面板 3 种子（n=600）"都跑过时，
**大面板会覆盖小面板**，这是设计行为。历史事故：r1A / ph3_* / g6_db04 只有单种子 n=200，
恢复"由母表重算"后它们全部掉回 init —— 不是数据丢失，是它们**从来没达到 n≥400**。

**处理办法只有一个：补种子（同一 tag 基名 + 新 seed），不要放宽门槛，也不要手改表。**

### 1.4 去重前先按权重 md5 判重名

`shuppet_specialist` 就是 `g8_bc_parent`（同一权重、README:306 明写）；所有 `port_*` 是同一个
`model.pt`。判断"某个驾驶员被覆盖了"之前，先 `md5sum build/agents/*/model.pt` 去重。

## 2. 固定评测流程（每次照抄，不许跳步）

```
① 定义格子四元组： (我方卡组, 对手卡组, 我方驾驶员, 对手驾驶员)
     —— 缺"对手驾驶员"这一维的记录一律视为无效（历史 98% 事故的根源）
② 多 seed：每格 ≥ 3 seed × N=200 Bo3（seed 固定 950000 / 950001 / 950002），池化 n≥600
     —— 单种子 n=200 的 Δ 噪声 ≈ ±6.9pp；单种子 n=1000 都能偏 5.5pp
③ 跑：
      TS=decks/testset_meta_A.tsv SEED=<seed> bash tools/meta_eval.sh \
          --cand build/agents/<X> --tag <base>_s<seed>
     ★ tag 基名必须已在 export_master.py 的 TAG2CELL 里登记，否则数据进不了母表（会静默丢）
④ 回传：orchestrate_cpu.sh 拉 logs/meta/<tag>/vs_*.json 回本地
⑤ 刷新母表并重算交付表（**只许这两步，不许手改**）：
      ./tools/py tools/export_master.py
      ./tools/py tools/build_from_master.py                    # b05 口径
      ./tools/py tools/build_from_master.py --weights decks/weights_top.txt --suffix _top
      ./tools/py tools/build_pilot_table.py
⑥ 校验：./tools/py tools/driver_registry.py check     # 表里每个名字都能解析成 agent/权重
⑦ 记录：把本次新增的 driver 登记进 tools/driver_registry.py；更新本文件"事故/变更"段
```

### 2.1 对手强度是结论的一半

对手驾驶员填 `init`（端口）的一格，只说明"我们比端口强"，**不能**用来下"我们很强"的结论。
同一副 f5f8：对手=端口时我们 6.7%，对手=`g8_bc_parent` 时我们 **8.5%**，
对手=`g8_shuppet`（强 PPO）时我们 **8.5~11.5%**；而母表里"对手=init"的格却是 98~100%。
⇒ 任何"我们打 X 有 98%"的说法，必须先报对手驾驶员是谁。

## 3. 名字注册表（`tools/driver_registry.py`）

- `DRIVERS`：名字 → `agent`（评估机目录）/ `weights`（本地）/ `remote`（GPU 机 .bin）/ `deck` / `fidelity`
- `ALIASES`：`shuppet_specialist → g8_bc_parent`、`port* → init`
- `RETIRED`：权重已丢失的历史名字（`bc_grookey3` / `ph3_db04_v1` / `ph3_9d6e_v1`），check 只提示
- 新增驾驶员：训完 → 存 `models/ppo/<name>.pt` → 推到 GPU 机 `/root/kl/<name>.bin` →
  **登记进 `DRIVERS`** → `driver_registry.py check` 通过 → 才能进表/进 bank。

调用方已经接好了：`make_testset_A.py`、`choice_to_banks.py` 都从注册表取，未知名字**直接报错退出**。

## 4. 禁止清单

1. ❌ 手改 `-choice.csv` / `-win-rate*.csv` / `-choice-self.csv`（下次重算就覆盖）
2. ❌ 只跑 1 个 seed 就判"某驾驶员更强"
3. ❌ 把两种权重口径的数字拼在同一张结论表里
4. ❌ 表里出现注册表没登记的名字却让脚本"回退 init"
5. ❌ 用"对手=端口"的胜率宣称某卡组/驾驶员强
6. ❌ 放宽 `VERIFIED_N` / `THRESH_CELL` 来"救回"某个驾驶员（只能补样本）
