# slowking（26c6）差距定位：我们的两个模型 vs ミワハルキ 的真人操作

数据与方法（可复现）：

```bash
./tools/py tools/bc_frame_diag.py --deck 26c6 --bc <模型> \
    --index data/distill_index.jsonl --games 25
```

- 样本：**3231 帧 / 25 局 / 1 个玩家**（ミワハルキ 的 26c6 slowking 真人回放）
- 口径：「同帧语义动作一致率」——把真人、我们的模型、端口三者各自的输出都映射到
  当前帧的候选索引 → 再映射到语义动作 `(类别, 子类, 卡, 目标)`，逐帧比对
- ⚠️ 真人动作**不是标准答案**；这里量的是"**像不像他**"，不是"对不对"

## 1. 总览

| 模型 | 一致率 | 与端口差 |
|---|---|---|
| `bc_pool/deck_26c6_.pt`（BC 克隆，135k 帧） | **91.0%** | +8.1pp |
| 端口 `port_plain` | 82.8% | — |
| `models/ppo/r1A.pt`（我们 10M 的 slowking 专才） | **80.5%** | **−2.4pp** |

## 2. 按动作类别拆开（帧数 / BC / 端口 / r1A）

| 真人类别 | 帧数 | BC | 端口 | r1A | 读法 |
|---|---|---|---|---|---|
| 选牌 | 1351 | 100.0% | 100.0% | 100.0% | 开局选先后手，无信息 |
| **打出**（物品/支援者/场地） | **755** | **83.8%** | 75.8% | 74.0% | **残差最大的一类** |
| **附着**（能量贴给谁） | 242 | **78.1%** | 75.2% | 74.0% | **最弱的一类** |
| 特性 | 229 | 89.1% | 66.8% | 63.8% | BC 学到位（+22pp） |
| 攻击（选招/选目标） | 224 | 83.9% | **49.1%** | 47.8% | 端口一半选错招，BC 学会了 |
| 换人 | 176 | 85.8% | 60.2% | 55.1% | BC 学到位（+26pp） |
| 进化 | 108 | 87.0% | 84.3% | **55.6%** | r1A 崩了（−29pp） |
| 结束回合（时机） | 82 | 79.3% | 57.3% | **45.1%** | r1A 崩了（−12pp） |

「条件偏离」：**BC 在真人"打出"时选择了"结束回合" 10 次**（= 直接把有用的动作跳过了）。

## 3. 结论

1. **BC 已经把端口完全不会的三件事学会了**：攻击选招（+34.8pp）、换人（+25.6pp）、
   特性链（+22.3pp）、结束时机（+22.0pp）。所以"会不会打这副牌"这一层，BC 已到位。
2. **BC 剩下的 9% 不一致高度集中在三类**：打出（16.2%）、附着（21.9%）、结束回合（20.7%）。
   这三类的共同点 = **同一回合内的顺序与资源分配**，不是"该不该做"，而是"先做哪个、贴在谁身上"。
3. **r1A 不能当"更接近真人"的答案**：它的整体一致率比端口还低（80.5% < 82.8%），
   进化（55.6%）、结束回合（45.1%）严重偏离。它本地分数高，是因为 RL 针对
   *我们自己的弱对手* 调出了非人类打法 —— 这正是"不能拿训练胜率当晋升依据"的又一例。

### 为什么"保真 91%"仍然实战弱（机制）

- 单帧模仿只看"这一刻点哪个"，而**顺序**的价值要等回合结束、甚至几个回合后才体现 ⇒
  训练信号里根本没有这一项。所以模型会"动作集合正确、顺序错误"。
- 26c6 是慢速控制牌组，赢法依赖多回合节奏 ⇒ 单帧模仿最吃亏。
  这也解释了历史上 `bc_26c6p` 同牌镜像只有 0.2625（< 端口）。

## 4. 训练一个"ミワハルキ 级 slowking"的路线

### ① 起点必须是 BC，不是 r1A

```
ANCHOR=slowpoke_slowking__26c6
INIT=bc_pool/deck_26c6_.pt        # 91% 一致的那个（不是 r1A）
LR=1e-4（比常规 2e-4 小一半，防止一上来就把风格冲掉）
T=4M
```

### ② 对手（陪练）用最强的那几个，考官留在池外

```
陪练：g8_bc_parent @0d86   （BC 克隆，学生打它 85.5%）
      deck_0d86_   @0d86   （BC 克隆，85.0%）
      g8_shuppet   @0d86   （PPO，86.0%）
      deck_f5f8_   @f5f8   （f5f8 的最强驾驶员，练"打 f5f8"这关）
      + 1 个通用（不绑牌）
考官（不进池）：
      · 一致率（真人帧，本工具）—— 必须 ≥ 88%（BC 基线 91%）
      · 对 g8_bc_parent 的胜率 —— 人类线是 61.4%（ミワハルキ slowking vs 别人的 shuppet）
      · 对 deck_f5f8_ 的胜率 —— 人类线约 50%
```

### ③ 防跑偏：训练器**没有** teacher-KL 锚

现在只有 per-minibatch 的 KL 守卫（相对**上一轮策略**，不是相对 BC 教师）。所以要靠流程：

- 每 16 epoch 存一次快照 → 每个快照跑一次 `bc_frame_diag`（6 分钟）→ 一致率跌破 88% 就回退，
  不用等 4M 跑完才发现"风格跑飞了"（r1A 就是这么跑飞的）
- 这条闸门可以自动化，纳入 `refresh_tables.sh` 之外的训练报告

### ④ 如果 RL 仍然把风格带跑

两个纯训练侧改法（都不需要新数据）：

- **类别加权 BC**：把 `打出 / 附着 / 结束回合` 的 loss 加权 2~3 倍，先把残差最大的三类压下去
- **回合级序列模仿**：把同一回合的多个动作当一个序列学（顺序就有监督信号了）
  —— 直接针对 §3.2 的机制问题

## 5. 立即可做的验证（不需要 GPU）

1. 把样本扩到 100 局（现在 25 局，一致率 ±1.5pp）→ 数字更硬
2. 把同一套审计套到 **f5f8 的 BC**（`deck_f5f8_`）上：如果同类残差（打出/附着/顺序）
   也占大头，说明这是我们所有克隆的通病，那"类别加权 + 回合级模仿"应该优先做
3. 训练前先测 **BC 的实战基线**：`bc_26c6` 对 g8_bc_parent / deck_f5f8_ 的胜率
   （现在只知道 88%/…，是同牌对手，不是 shuppet/f5f8）

# 追加（同一回合内的"顺序脚本"才是真差距）

## A. 100 局版（13,682 帧，slokwing BC）

| 类别 | 帧数 | BC | 端口 | Δ |
|---|---|---|---|---|
| 总体 | 13,682 | **91.6%** | 83.8% | +7.8 |
| 打出 | 3,262 | 85.5% | 78.0% | +7.5 |
| **附着** | 1,016 | **78.1%** | 77.4% | **+0.8**（等于没学到） |
| 特性 | 1,014 | 91.3% | 69.2% | +22.1 |
| 攻击 | 940 | 86.7% | 54.0% | +32.7 |
| 换人 | 721 | 82.4% | 57.6% | +24.8 |
| 进化 | 442 | 84.6% | 81.0% | +3.6 |
| 结束回合 | 344 | 84.9% | 60.8% | +24.1 |

## B. 不一致时模型"改做了什么"（`--dump <类别>`）

**当真人贴能量时**（`area=5` = **后场 BENCH**，下标 0/1/2…）：

| 牌组 | 不一致帧 | 模型改做 | 占比 |
|---|---|---|---|
| slowking 26c6 | 53 | **打出** | 73.6% |
| | | 换人 / 特性 / 进化 | 9.4% / 7.5% / 7.5% |
| f5f8 | 180 | **打出** | 62.2% |
| | | 进化 / 特性 | 17.8% / 15.0% |

样例（f5f8）：`真人=附着(area=5 idx=1)` vs `BC=打出[Poké Pad]`、`BC=打出[Fezandipiti ex]`、`BC=打出[Pikipek]`。

**反过来，当真人"打出"时**（slowking，122 帧不一致）：模型改去 `附着 35.2% / 换人 21.3% / 特性 13.9% / 进化 12.3% / 攻击 9.0% / 结束回合 8.2%`。

⇒ **这不是随机错，是"回合内动作优先级脚本"不同**：真人先贴能量（而且贴后场，为 2~3 回合后的攻击手蓄能），我们的模型先打牌/进化/用特性，能量就漏了。而能量是**不可逆的长期投资**，漏一次就少一次。

## C. 为什么"保真 91.6%"仍然弱（机制）

BC 是逐帧模仿：某状态的标签 = 真人当时的**下一个动作**，它隐含依赖"本回合已经做过什么"。
模型一旦在某个回合里先偏离（先打牌），就走到"还没贴能量"的分支，而这个分支在真人数据里几乎不出现
⇒ 它没有"回头补贴能量"的监督信号。一局漏 3~5 次，slowking 这种慢速控制牌组正是靠
"每回合不浪费一次能量/一次进化"取胜的。

## D. 三条修法（按成本排序）

1. **规则补丁（最便宜，几小时）**：agent 输出前加一条——"本回合还没 attach、手上有能量 ⇒ 优先
   attach 到后场/指定目标"。用 `audit_decisions.py` 的套路先量化违规次数，再用 200 场镜像 +
   对 `g8_bc_parent` 验证是否真涨（人类顺序不一定最优，必须实测）
2. **回合级序列模仿（对症，1~2 天）**：`bc_materialize` 里按 `(file, seat, turn)` 分组，
   训练目标改成"整回合动作集合 + 顺序"，漏贴能量直接被惩罚
3. **RL 特攻（我们原本的计划）**：reward 天然含"漏能量 → 两回合后打不动"，但**起点必须是 BC**
   （见 §4 ①），否则会像 r1A 那样学成非人类风格（80.5% < 端口 82.8%）
