# 投资分口径：训练资源向「高分卡组 + 高覆盖率」倾斜

用户 2026-11-19 定的方向（原话）：
> 我们的训练资源要向高分卡组和高覆盖率两个方向倾斜，所以我们的投资分必须考虑我们本地的分和远端高分的差距，
> 以及卡组在我们对手中的覆盖率，进行选择。

## 1. 公式（`tools/build_investment_score.py`）

```
投资分 = 100 × ( G × C × H ) ^ (1/3)
```

| 项 | 定义 | 数据来源 | 缺失时 |
|---|---|---|---|
| **缺口 G** | `clip((远端天花板 − 我们在这副牌上的最高分) / 400, 0, 1)` | 远端天花板：榜前队回放里「某玩家这副牌 ≥10 局且 ≥50% 胜率」时的**最新榜单分**（标签带玩家名+分，见 `docs/必须卡组清单.csv`）；我们的分：`data/lb_ours_by_deck.json` | 远端有分但我们没打过 ⇒ **G=1**（全是可赚的）；连远端天花板都没有 ⇒ **G=0.5**（中性） |
| **覆盖 C** | `份额 / 全场最大份额`（线性） | `对手覆盖率` = 该牌在**所有真实对局**里被使用的比例：`logs/sub_feedback/scan.jsonl` 的对手边 + `epsoide_top*/` 榜前队回放的**双方**（合计 1167 次出场） | — |
| **高峰 H** | `clip((远端天花板 − 600)/1000, 0.2, 1)` | 同 G；没有天花板就用该牌天梯实测胜率 `/0.6`，再没有就用榜前队胜率 `/0.6` | 0.35 |

要点：
- **G 只用"远端"天花板**，不掺我们自己的历史最高分 —— 自己持有记录只说明"这牌我们打到头了"，不代表没有空间。
- **C 用线性**（早期试过开方）：用户要的就是"高覆盖率优先"，开方会把 18% 的 3eaa 和 2.5% 的小牌拉开不够。
- **H 单独存在**是为了不让"覆盖高但牌很弱"（如 7e39，天梯胜率 33.3%）霸榜。

## 2. 「必须卡组」= 表里必须出现的牌（`tools/required_decks.py`）

三路并集（28 副，2026-11-19）：

1. `decks/testset_meta_real.tsv` 的 **17 个真实份额格**（评测口径必须覆盖的对手）；
2. `docs/the-pockmon-battle-choice-in-table.csv`（母表）里已有的牌；
3. `epsoide_top*/` 回放里**榜前 N 队用过且 ≥10 局**的牌。

每副牌都给出：`对手覆盖率` / `覆盖率(我方对局)` / 榜前 N 队局数与胜率 / 回放口径天花板+玩家 /
`已训练驾驶员` / `现有驾驶员` / `建议`。

## 3. 没有模型时怎么办（`tools/materialize_required_drivers.py`）

按顺序取第一个：
1. 已有**训练过**的驾驶员（`build/agents/*` 里解开同样 60 张卡、且 model 与端口权重不同）⇒ 不动；
2. 该原型有 **BC 权重**（`bc_*` / `models/ppo/*bc*.pt`）⇒ 铺 `bc_<4hex>`；
3. 否则铺 `init_<4hex>`（端口权重 `build/port_plain/model.pt`）。

补出来的 agent 用**硬链接**指向同一份权重（20 MB × 28 副不重复占盘），并自动登记进
`tools/driver_registry.py`（幂等，已有就跳过）。2026-11-19 首跑补了 20 副（6 BC + 14 init）。

## 4. 刷新流程里的硬闸门

`tools/refresh_tables.sh` 现在是 ①母表 →②③交付表 →**④必须卡组清单 →⑤补驾驶员**→⑥名字校验
→**⑦投资分**→**⑧覆盖校验**→⑨方案A 测试集。第 ⑧ 步 `required_decks.py --check-covered`
会在"投资分表没覆盖全部必须卡组"时**非零退出**，整条刷新失败 —— 不允许表里悄悄少一副牌。
