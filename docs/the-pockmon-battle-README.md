# 三张 battle 表的填充说明

生成器：`tools/build_battle_tables.py`（可重跑，幂等覆盖）

```bash
./tools/py tools/build_battle_tables.py
```

## 编码与格式

- **编码 GB18030**（模板原本是 GBK；选手名含越南语/土耳其语字符，GBK 编不下，故用其超集）。
  Excel 直接双击可正常显示。
- 表头与模板**逐字一致**，未增删列。

## cards.csv —— 卡组宇宙（119 行）

| 列 | 口径 |
|---|---|
| `DeckID` | 卡组哈希前 4 位（如 `7e39`、`26c6`） |
| `卡组` | 全名 `<archetype>__<hash>`（来自 `decks/pool_field/` 的 187 副 + 档案里的 8 位哈希） |
| `Meta 占比` | 在 **1756 局真人天梯档案**（`data/ladder_games.tsv`）里的出现占比，单位 % |
| `样本局数` | **座位出现次数**（一局有 2 个座位，故 1000 ≈ 500 局） |

⚠️ **口径提醒**：这里的 Meta 来自我们抓取的**真人高分回放档案**，其中两位选手（ミワハルキ、YumeNeko）
贡献了大量对局，所以 `26c6`/`0d86` 都显示 28.47%（各 1000 座位）——**这是档案采样偏差，不是真实天梯分布**。
我们自己的实测场地（582 局 / 640 条）另见 `docs/opponent_pool_weights.md`：
那里 7e39 34.7%、2617 11.7%、e8ee 6.2%、f5f8 5.7%、0d86 5.5%……

## match.csv —— 对位记录（616 行 = 三块拼接）

用 `玩家` 列区分来源：

| 块 | 行数 | `玩家` / `对手` 列 | 来源 |
|---|---|---|---|
| ① 真人 vs 真人 | 92 | 选手名（如 `YumeNeko`） | `data/ladder_games.tsv`，同 (卡组,选手)×(卡组,选手) 组合 **≥3 局**才收录 |
| ② 我们 vs 对手 | 475 | 我们的提交件名（如 `g6_db04`）/ 对手选手名 | `data/our_games.tsv`，640 局 |
| ③ 端口 vs 端口 | 49 | 两边都是 `端口权重` | `data/scheduler/matrix_full.csv`，7×7 矩阵，每格 200–300 局 |

- `胜局/败局` 由原始记录聚合；`平局` **全部为 0**——我们的数据源里没有平局记录，不是漏填。
- ① 块里同一对选手的两个方向会各占一行（座位先后不同，胜率本就不同，不做对称化）。

## players.csv —— 选手与克隆体（104 行）

| 列 | 口径 |
|---|---|
| `DeckID` / `卡组` | 同 cards.csv |
| `玩家` | 真人选手名，或我们本地的 agent 目录名 |
| `类型` | `真人` / `端口基线` / `BC克隆` / `PPO训练` |
| `父玩家` | 克隆体的启发来源：BC 克隆填其语料贡献最大的真人教师；端口/PPO 留空 |
| `Checkpoint` | 本地权重路径 `build/agents/<name>/model.pt`；真人为空 |
| `数据来源` | 真人是 `Kaggle 回放（N 局）`；本地 agent 是 `端口仓库权重` / `我们训练` |

**类型是按权重身份判定的，不是按目录名前缀**：

| 权重 md5（前 12） | 判定 | 例子 |
|---|---|---|
| `8b5fcda672ac` | 端口基线 | `port_7e39`、`c_grookey`、`port_0904`… 共 12 个 |
| `6007d6f083` | BC克隆 | `g8_bc_parent`、`opp_shuppet_human` |
| 其它 | PPO训练 | `g6_db04`、`g8_shuppet`、`ph3_2617_v2`… 共 8 个 |

（这条判定规则是踩坑后加的：早期按目录名前缀分类，把 `opp_shuppet_human` 误判成端口权重，
它其实是 shuppet 的 BC 父权重。）

## 已知缺口

1. **冠军卡组的真人样本极少**：`0904`(Petit Canard 1510)、`e1d7`(ミワハルキ 1580) 在我们抓的档案里
   几乎不出现，cards.csv 里占比为 0 —— 不是没有玩家打，是没抓到回放。
2. **平局数据缺失**（见上）。
3. `DeckID` 只保留 4 位哈希，理论上可能撞车（目前 119 副无冲突）。
