# 提交复盘 → 下一步训练：口径、判据与流水线

> 这份文档解决一个具体问题：**提交之后拿到的数据，怎么变成"下一轮训什么"的决定**。
> 起因是 2026-11-16 的那轮"补短板"实验——我们凭"哪格难看"挑了 3eaa，
> 烧掉一小时 GPU 只换回 +2.0pp（面板 0.55pp），而真正值钱的是权重和可行性两件事。

## 1. 为什么 LB 分数本身没用，回放才有用

| 渠道 | 能给出 | 不能给出 |
|---|---|---|
| LB 分数 | 一个标量（team = 两臂最大值） | 输给谁、哪一格在流血、对手构成 |
| 提交后的**对局回放** | 真实对手的**完整 60 张卡表**（`steps[1][j].action`）、座位、胜负 | 对手策略权重（永远看不到） |

所以复盘入口只有一个：**先提交 → 抓回放 → 统计**。
抓取用 `framework/replay.py` 的 `decks_of()` / `our_index()`（**不要自己解析 steps**：
Kaggle 的 `action` 记在下一步，同一步配对会整体错位一位，这个坑已经写在那份文件头里）。

## 2. 一键流水线

```bash
# 提交拿到 ref 之后（refs 在 LB / My Submissions 里）
bash tools/sub_feedback.sh <ref1> <ref2>

# 已经有回放（epsoide_sub*）时只做分析
SKIP_FETCH=1 bash tools/sub_feedback.sh

# 复算任意历史回放目录（自测用，不会动共享权重）
SUB_DIRS=epsoide_seat SKIP_FETCH=1 bash tools/sub_feedback.sh
```

产出（`logs/sub_feedback/`）：

| 步骤 | 产物 | 用来回答 |
|---|---|---|
| ② `verify_sub_dataset.py` | `verify_*.log` | 我方是不是始终同一副牌、座位能否判定（数据可信度） |
| ③ `analyze_opponents.py` | `opponents.log` | 真实对手构成（相近配置合并）+ 对每种卡组的胜率/Wilson CI |
| ④ 内置脚本 | `decks/weights_field_real.txt` | **真实场地权重**（替代自家口径的 b05） |
| ⑤ 内置脚本 | `decision.csv` | **决策表**：份额 × 参考线 × 真人帧数 × 可行性 |

> ④ 特意**不**调用 `tools/build_field_pool.py`：那个工具会重命名池内卡组文件并覆盖
> `decks/weights_top.txt` 等共享权重（2026-11-16 自测时踩到一次，已回滚）。复盘流程不得改动现有权重。

## 3. 决策表怎么读

列含义：

- **真实份额**：该对手卡组在对局里出现的比例（对手侧计数，一场一记）。
- **我方胜率**：回放里对该卡组的实际胜率（含 Wilson CI，样本小就别当结论）。
- **参考线**：母表里"端口权重 vs 端口权重"的该格胜率——即**任何驾驶员都该达到的水平**，
  用它当"这一格还有多少空间"的尺子，而不是拿我们的最优数字当上限。
- **真人帧**：`data/distill_index.jsonl` 里该卡组的真人决策帧数，决定"训不训得动"。
- **目标价值** = 真实份额 × 参考线，即"这一格理论上能贡献多少个面板点"的上限。

**判读规则（写死，不再每次商量）**：

1. 目标价值 < **0.5pp** ⇒ 不投入（登记即可）。3eaa 就是这一类：份额 3.6%、上限 0.55pp。
2. 真人帧 < **2000** ⇒ 不可训（联盟里没有"人怎么打这副牌"的信号，梯度只能学到打赢机器陪练）。
3. 目标价值 ≥0.5pp **且** 真人帧 ≥5000 ⇒ 才值得开 GPU；按目标价值降序排优先级。
4. 份额和我方胜率都用回放算，**不要**再把 b05 当分母：它是我们自家 582 局的历史，
   与真实天梯偏差极大（见 4）。

## 4. 已经知道的偏差（等回放确认后替换）

| 卡组 | b05（自家口径） | 顶分段实际 | 结论 |
|---|---|---|---|
| `teal_mask_ogerpon_ex_applin__7e39` | 35.0% | **1.2%** | 权重被高估约 30 倍 |
| `shuppet_dhelmise__0d86` | 9.7% | **43.5%** | 被低估 4 倍 |
| `dreepy_drakloak__3eaa` | 3.6% | 更低（老回放里 0.6%） | 优化它没有意义 |

⇒ f5f8 行此前有三分之一权重压在一个"实际几乎没人打"的对手上；真正该吃满的是 shuppet（顶分段 43.5%）。
**先校准分母，再谈"补哪一格"**——这是本轮最大的方法论收获。

## 5. 复盘之后的标准动作

1. `decks/weights_field_real.txt` 出来 → 用 `tools/build_prompt...`（无）直接用：
   `TS=decks/testset_meta_A.tsv` 的面板权重要改成这一份，重算面板分，与 b05 口径的结果并列记录。
2. 按第 3 节规则挑 1–2 个目标格 → 用 `tools/pick_banks.py` 选 bank（分数 = 份额 × 梯度 × 威胁），
   `tools/specialist_shuppet.sh` 起训（`LEAGUE_TOTAL` / `EXTRA_BANKS` / `EXTRA_DECKS`）。
3. 训完按预注册判据验收（单格 ≥+5pp、面板降 ≤2pp、关键格不掉），再决定是否换提交位。
4. 全程用 `tools/refresh_tables.sh` 刷表、`tools/git_snapshot.sh --push` 提交，别手工改表。

## 6. 本轮（方案 B）期望的复盘输出

两臂都是 f5f8 卡组（`candf5f8S` 61.3% / `candf5f8G` 62.7%），因此回放给的信息是：

- **同一副牌在不同驾驶员下的真实胜率**：如果 f5f8G 的 LB 分数更高，说明 2617 那 1.4pp 在真实场里兑现了；
  如果两者几乎相同，说明真实场里 2617/3eaa 的份额远低于 b05（预期如此），**下一轮该按真实份额重排目标**。
- **真实对手构成**：用它替换 b05，回答"shuppet 43.5% 的大盘我们到底打到多少"——
  我们现在对 shuppet 的本地数字是 90%，如果真实场只有 60%，那是比任何单格补短板都大得多的洞。
